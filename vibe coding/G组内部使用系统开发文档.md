4.分析现有的系统建议月销计算逻辑，我感觉现在的计算逻辑还是不够完善和完美，目前系统建议月销根据7/14/30日销量计算的，规则如下：

| 低销量分界 | 10  | 30日销量低于该值时使用低销量权重 |
| ----- | --- | ----------------- |
| 高销量分界 | 30  | 30日销量达到该值时使用高销量权重 |
|       |     |                   |

|销量档位|M1 最近7日|M2 第8—14日|M3 第15—30日|权重合计|
|---|---|---|---|---|
|低销量|30.0%|25.0%|45.0%|100.0%|
|中销量|40.0%|30.0%|30.0%|100.0%|
|高销量|50.0%|30.0%|20.0%|100.0%|

我感觉这权重设置的有点问题，低销量的时候应该以最近7天的权重更多点吧？然后就是比如一个品很久没有销量，我因为降价并且开了广告销量激增，这个时候怎么设置月销比较好呢？然后就是有一列产品属性，单元格可能是夏季品、冬季品和常规品，如果是季节性，起售以及夏天快过去的时候，是不是直接用7天的月销比较好呢或者7天销量的权重应该很大，我感觉系统建议月销应该分的更详细更多情况，同时用上趋势差异率、销量状态、产品属性等综合判断

5.最终补货月销，不根据补货状态列设置为0，一直跟系统建议月销保持一致，然后预测可信度为低的时候填充蓝色，随后蓝色的让人工审核修改，因为清库存状态我只是不补货了，还是要看到它的月销的。
